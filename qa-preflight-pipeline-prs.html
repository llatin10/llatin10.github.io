Why a digits-only line comes out reversed in a Hebrew app

The first iOS dry run missed OZ-137622. The shared core gained a right-to-left order rule because of it.

A line's direction comes from its first strongly directional character. A branch and account number joined by a hyphen has no Hebrew letter at all, so the Unicode Bidirectional Algorithm lays it out left to right, even on a right-aligned Hebrew screen. A right-to-left mark (U+200F) around the value fixes it. Try it:

synthetic values
copy "{{ACCOUNT_NUMBER}} - 001", no mark

שלום, דנה

Shows account first: parts reversed

same copy, wrapped in U+200F

שלום, דנה

Branch first, as the design shows

The rule now weighs every candidate copy (bundled strings, Lokalise, design samples). A line whose only Hebrew letter comes from copy delivered at runtime is 🟡 at best unless the code sets the direction, because the second dry run trusted a bundled string that lagged Lokalise.

Draft, posted only after approval

Run it with a bug key (/fix-confidence OZ-…) or a fix PR (/fix-confidence android-banking#…, open or merged, one report per bug key it names). A fix always lives in the bug's own platform repo. An open PR is read at its latest commit, so a check before merge can catch a regression while it's still cheap to fix.

Each report is published as a page and never committed. The Jira comment (score, an incomplete-fix line when there is one, possible regressions with their links, retest steps) is posted on the bug only after the QA owner approves its text; for an open fix PR, a short developer comment can go on the PR the same way. Only behavior that worked before the fix counts as a regression; other issues in the area are left out. In a QA-plan PR, each Fixed bug in the bug snapshot gets a chip such as AI 🟡 44 · 2🔴 2🟡 · fix incomplete.

One method, two apps

The pre-flight is a shared core, byte-identical in android-banking and ios-banking, plus a small per-repo profile. A manifest of hashes and a CI job keep the copies honest.

Shared core (identical bytes)

  • the rulebook dev-preflight-checklist.md
  • the command /tp-confidence
  • the page template and lessons log
  • checker, assembler, manifest, tests and fixtures
  • the preflight-tooling CI workflow
=sha256 manifest
CI fails on drift

Per-repo profile

  • repo, ticket-key pattern, folder rule
  • build & test commands (Gradle / xcodebuild)
  • string keys, accessibility ids, deep links
  • feature flags, analytics, shared state, lint
  • the directional helper for the RTL rule

QA's full test plans stay Android-only; iOS developers get the self-check without the QA rulebook.
